# 产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | SVN 企业文档客户端（暂定） |
| 目标平台 | macOS 26+ |
| 产品形态 | 原生桌面客户端 |
| 文档状态 | 初稿 |
| 目标版本 | V1—V3 |

## 2. 背景与问题

许多企业使用 SVN 保存了多年积累的合同、项目材料、设计文件、管理制度和技术资料。传统 SVN 客户端主要面向开发者，暴露 Working Copy、Commit、Branch、Merge 和 Conflict 等概念，普通员工学习成本较高。

本产品以“企业文档云盘”为交互模型：用户看到目录、文件和历史版本，底层仍使用 SVN 完成存储、提交和审计。产品不取代 SVN 服务端，也不改变仓库既有目录与权限体系。

## 3. 产品目标

### 3.1 目标

- 让非技术用户像使用 Finder 或企业网盘一样浏览和管理 SVN 文档。
- 覆盖日常文档管理的基础操作，并完整保留 SVN 历史。
- 在大型仓库中通过懒加载、目录缓存、搜索和收藏提升定位效率。
- 对失败、权限不足和并发修改提供易理解、可恢复的反馈。

### 3.2 成功指标

- 新用户无需理解 SVN 术语即可独立完成浏览、下载、上传、替换、重命名和删除。
- 正常网络下，进入任意已展开目录后能快速看到首屏内容；大目录加载不阻塞界面。
- 所有内容变更均产生可追溯的 SVN revision，并能在历史中查看。
- 重命名使用 SVN move 语义，替换保留同一路径的版本历史。
- 失败操作不会让本地缓存或界面显示为已成功。

## 4. 用户角色

### 4.1 普通员工

- 浏览、搜索、下载和打开文档。
- 在有权限的目录上传、替换、重命名或删除内容。
- 查看文件信息与历史版本。

### 4.2 资料维护人员

- 维护目录结构和公共资料。
- 恢复历史版本，核对修改人、时间和提交说明。
- 使用收藏快速进入高频目录。

### 4.3 管理员

- 配置仓库入口和认证方式。
- 依赖 SVN 服务端管理路径权限。
- 排查连接、证书、权限及操作失败问题。

## 5. 设计原则

- 使用用户语言：界面显示“上传”“替换”“历史版本”，不显示 add、commit、revision graph 等实现细节。
- 历史优先：移动、替换和恢复必须尽可能保留可追溯历史。
- 显式确认高风险操作：删除、替换、恢复前说明影响对象。
- 大仓库友好：目录按需加载，长任务可取消，界面始终保持响应。
- 服务端为事实来源：本地数据用于缓存和体验优化，不作为仓库状态的最终依据。

## 6. 信息架构

```text
应用

```

## 7. 功能需求

### 7.1 V1：核心可用版

#### FR-01 仓库连接

用户可以新增、编辑和移除仓库配置，并验证连接。

仓库配置至少包含：

- 显示名称。
- 仓库 URL，支持服务端实际启用的 `http://`、`https://`、`svn://`、`svn+ssh://`，并允许开发/测试使用 `file://`。
- 用户名和密码；密码只保存到 macOS Keychain。
- HTTPS 证书策略：严格验证、允许自签名/未知 CA，或在明确风险提示后允许全部证书错误。
- 可选的默认起始路径。

验收标准：

- 验证成功后可以进入仓库根目录或配置的起始目录。
- 首次启动且没有已保存服务器时，自动打开添加服务器页面。
- “测试连接”不保存配置；“保存并连接”必须先连接成功，再保存配置和凭据。
- 认证失败、证书问题、网络失败和地址无效有不同的中文提示。
- 密码或令牌不以明文写入配置文件或日志。
- 放宽证书校验仅作用于当前 HTTPS 服务器配置，不改变其他服务器或系统的信任设置。
- 连接测试和交互式目录/元数据读取等待超过 10 秒时终止命令，并提示用户检查地址和网络；文件传输不使用 10 秒总时长，避免误伤大文件。

#### FR-02 目录树与文件列表

用户可以按目录浏览仓库。左侧目录树和右侧文件列表都允许按需展开文件夹；右侧顶层仍表示当前目录的直接子项。

列表字段：

- 名称和文件类型图标。
- 类型（文件/文件夹）。
- 文件大小，目录可留空。
- 最后修改时间。
- 最后修改人。
- 版本号（revision）。

验收标准：

- 双击目录进入，面包屑可返回任意上级目录。
- 点击目录行的披露箭头可原地展开或收起，不改变面包屑和当前上传目录。
- 展开子目录优先使用目录缓存；刷新、排序和普通状态更新不得无故重置已展开节点。
- Finder 文件拖到展开视图中的目录行时上传到该目录，拖到空白区域时上传到当前面包屑目录。
- 支持按名称、大小、修改时间排序。
- 支持刷新当前目录。
- 空目录、加载中、无权限和加载失败均有明确状态。

#### FR-03 下载

用户选择本地位置后下载文件或文件夹。文件夹下载需递归导出内容。

验收标准：

- 下载任务显示进度、目标位置、完成或失败状态。
- 状态栏可查看最近传输记录和失败原因；下载任务支持取消。
- 已存在同名本地文件时，要求用户选择替换、保留两者或取消。
- 取消或失败不留下被误认为完整文件的最终产物。

#### FR-04 下载并打开

用户双击文件或选择“打开”，客户端将文件下载到受管理的临时缓存，再使用 macOS 默认应用打开。

验收标准：

- 再次打开未变化的版本时可复用有效缓存。
- 缓存文件不存在或 revision 已更新时重新下载。
- 找不到可打开该格式的应用时给出可理解提示。

#### FR-05 上传文件

用户可以向有写权限的目录上传一个或多个文件。

业务规则：

- 新名称不存在时执行新增并提交。
- 同名文件已存在时不静默覆盖，进入“替换文件”确认流程。
- 默认提交说明由客户端生成，用户可在提交前修改。

验收标准：

- 上传成功后刷新目录并显示服务端 revision。
- 多文件上传应明确是一次整体提交还是多个独立提交；V1 默认一次选择对应一次提交。
- 任一文件校验失败时，提交前中止并说明具体文件。

#### FR-06 替换文件

用户选择本地文件替换仓库中的既有文件，仓库路径保持不变并产生新版本。

业务规则：

- 确认框显示仓库文件名、本地文件名、大小和修改时间。
- 默认要求本地文件名与目标一致；从“替换”入口选择不同名称时，内容覆盖目标但不改变目标名称，并再次明确提示。
- 提交前检查目标 revision 是否仍与开始操作时一致。

验收标准：

- 替换完成后，原有路径的历史连续可查。
- 发现远端已更新时不得直接覆盖，提示刷新后重试或另存上传。

#### FR-07 新建文件夹

用户可在当前目录创建文件夹。

验收标准：

- 名称为空、包含服务端不允许字符或与现有项目重名时不可提交。
- 创建成功后进入可见状态并产生 revision。

#### FR-08 重命名

用户可以重命名文件或文件夹，底层必须使用 SVN move/copy-history 语义，而非删除后重新上传。

验收标准：

- 重命名后历史仍可追溯到旧路径。
- 目标名称已存在时阻止操作并给出提示。
- 操作成功后目录树、列表和收藏中的路径同步更新。

#### FR-09 删除

用户可以删除文件或文件夹。删除产生 SVN revision，不提供单独回收站。

验收标准：

- 删除前显示名称；目录还需提示会删除全部子项。
- 用户必须显式确认。
- 删除记录可从 SVN 历史追溯，并可在后续版本中恢复。

#### FR-10 查看信息

用户可查看：名称、完整仓库路径、类型、大小、最后修改时间、修改人、最后修改 revision，以及可获得的 SVN 属性。

验收标准：

- 信息来自当前服务端状态或标注了缓存时间。
- 支持复制字段值。

#### FR-11 复制文件位置

右键菜单提供：

- 复制显示路径，例如 `公司文档 / 技术部 / SDK / 接口说明.pdf`。
- 复制仓库 URL，例如 `https://svn.example.com/repo/技术部/SDK/接口说明.pdf`。

复制内容必须对 URL 路径进行正确编码，同时保持展示路径可读。

### 7.2 V1.5：大仓库体验

#### FR-12 收藏

- 文件夹和文件均可收藏，优先支持文件夹。
- 收藏仅保存在当前设备与当前用户本地。
- 目标被重命名时尽可能更新路径；目标不存在时标记失效并允许移除。

#### FR-13 最近访问（已移出范围）

- 当前版本不提供最近访问入口，也不采集或保存文件、目录的访问记录。
- 保留编号仅用于需求追踪，后续除非重新立项，不实现该功能。

#### FR-14 文件名搜索

- 支持在当前目录或整个已配置搜索范围中按文件/文件夹名称搜索。
- 默认使用本地索引，展示索引更新时间并允许刷新。
- 支持大小写不敏感的包含匹配；后续可扩展类型和时间筛选。
- V1.5 不解析 Word、PDF 等文件内容。

### 7.3 V2：历史版本

#### FR-15 查看历史

每条记录显示 revision、作者、提交时间和提交说明。

当前客户端从文件右键菜单进入独立历史窗口，首批最多加载 100 条记录；历史查询使用当前节点的 peg revision，保证重命名后的文件仍能沿复制历史向前追溯。

#### FR-16 下载历史版本

用户可将指定 revision 的文件下载到本地，不改变仓库当前版本。

用户也可以将历史版本下载到受管理的 revision 缓存并直接用默认应用打开。

#### FR-17 恢复历史版本

“恢复”不是回退服务器 revision，而是读取选定历史内容并以一次新的提交写回当前路径，使恢复动作本身可审计。

验收标准：

- 提交前展示“选定版本”和“当前版本”。
- 当前版本在确认后发生变化时阻止恢复并要求刷新。
- 恢复成功生成新的 revision，历史链保持完整。

#### FR-18 文本差异（可选）

- 优先支持纯文本和代码文件。
- Word、Excel、PDF 不在首期差异范围内。

### 7.4 V3：企业增强

#### FR-19 权限提示

- 尽可能提前禁用无权限操作。
- SVN 权限通常无法完整预取时，以实际命令返回结果为准，不能把预测结果视为授权依据。
- 提示使用“没有读取/修改该位置的权限”，不显示原始命令行错误作为主文案。

#### FR-20 操作记录

- 客户端可展示由 SVN 历史推导出的文件操作记录。
- 本地诊断日志记录任务类型、时间、脱敏路径、结果和错误码，不记录密码或完整敏感内容。
- 若企业需要独立审计，应由服务端日志或专用审计系统承担，客户端不宣称本地日志不可篡改。

## 8. 通用业务规则

### 8.1 提交说明

所有写操作都必须带提交说明。默认模板：

| 操作 | 默认说明 |
| --- | --- |
| 上传 | `上传：{名称}` |
| 替换 | `更新：{名称}` |
| 新建文件夹 | `新建文件夹：{名称}` |
| 重命名 | `重命名：{旧名称} → {新名称}` |
| 删除 | `删除：{名称}` |
| 恢复 | `恢复：{名称} 至 r{历史版本}` |

### 8.2 并发修改

每个写操作在执行前记录目标或父目录的基准 revision，提交时进行乐观并发检查。若仓库已变化：

1. 不静默覆盖。
2. 保留用户尚未提交的本地来源文件。
3. 提示刷新并展示变化对象。
4. 允许用户重新确认后发起新操作。

### 8.3 名称与路径

- 展示层使用面包屑和可读路径，传输层使用规范化 URL。
- 必须正确处理空格、中文、`#`、`%` 等需要 URL 编码的字符。
- 禁止空名称、`.`、`..` 和包含路径分隔符的单个名称。
- 大小写冲突需按服务端文件系统和仓库行为实际验证。

### 8.4 刷新与一致性

- 写操作只有在 SVN 命令成功并返回 revision 后才更新为“已完成”。
- 成功后使目标目录缓存失效并重新加载。
- 离线时允许查看明确标注的缓存数据，但不允许执行写操作。

## 9. 非功能需求

### 9.1 性能

- 目录按需加载，禁止启动时递归读取整个仓库。
- 目录内容和元数据请求在后台执行，不阻塞主线程。
- 搜索索引增量更新，可取消全量构建。
- 大文件使用流式复制，并避免整文件读入内存。

### 9.2 安全

- 凭据存入 macOS Keychain。
- 默认校验证书；首次遇到未知证书时展示指纹和风险，不默认永久信任。
- 命令参数不得通过字符串拼接交给 shell，避免路径导致命令注入。
- 日志和错误上报必须脱敏。

### 9.3 可用性与可访问性

- 支持键盘导航、VoiceOver 标签和系统深浅色模式。
-  destructive 操作不可只用颜色区分。
- 长任务显示进度并支持取消；完成后提供“在 Finder 中显示”。

### 9.4 兼容性

- 最低系统版本固定为 macOS 26，不为旧版 macOS 增加兼容分支。
- 使用 Swift 6 语言模式和严格并发检查。
- 对支持的 SVN 客户端版本和仓库协议建立兼容性矩阵。
- 文件名采用 Unicode，必须对组合字符差异进行测试。

## 10. 不在范围内

- 回收站。
- 分支、标签、合并与冲突编辑器。
- 面向开发者的 Working Copy 管理。
- Office/PDF 全文检索。
- Office 文档语义差异。
- 自建用户、用户组和 ACL 管理。
- 跨组织的公开分享链接。

## 11. 发布验收建议

V1 发布前至少通过以下端到端场景：

1. 使用 HTTPS 和有效凭据连接测试仓库。
2. 浏览含 1,000 个直接子项的目录，界面保持可操作。
3. 上传中文名和带空格文件，随后下载校验内容一致。
4. 替换文件并在 SVN 历史中看到同一路径的新 revision。
5. 重命名文件和目录，确认历史可追溯到旧路径。
6. 删除非空目录，确认二次提示与仓库 revision。
7. 两个客户端同时修改同一文件，后提交者收到并发提示且不能静默覆盖。
8. 断网、认证过期、无权限和证书异常均显示正确状态。
